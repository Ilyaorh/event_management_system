# Контроль версий

## Что хранится в репозитории

В Git находятся исходники C#, проекты, решение, тесты, документация и примеры запросов без секретов. Исключаются `bin/`, `obj/`, локальные настройки IDE, тестовые результаты, файлы SQLite и временные секреты. Правила приведены в `.gitignore`; `git check-ignore -v путь` позволяет проверить совпадение. Уже отслеженные файлы сам `.gitignore` не удаляет: для этого требуется `git rm --cached`.

Токены, пароли, закрытые ключи и реальные строки подключения не публикуются. Если секрет попал в историю, его необходимо отозвать и заменить, а затем оценить очистку истории и копий; удаление файла без отзыва не устраняет риск.

## Ветки, сообщения, слияние

`main` хранит объединённую версию; каждому этапу соответствует своя ветка `stage/NN-*`. Для интеграции отдельно ведутся `feature/*` ветки. Изменения разбиваются на логические коммиты с короткими описаниями по-русски. Перед объединением проверяются статус, различия, сборка и тесты, после - результат слияния. Публичную историю не переписывать без отдельного согласия.

## Учебный конфликт

На этапе 2 одна правка файла сохраняется в `git stash`, другая фиксируется в той же ветке. Затем `git stash apply` создаёт конфликт той же строки. Разрешённый файл добавляется через `git add` и фиксируется; использованный stash удаляется. Это учебное воспроизведение конфликта, а не имитация двух настоящих участников. Подробности и результат приведены в отчёте этапа.

Контрольная точка - тег `stage-02-checkpoint`. Граф: `git log --oneline --graph --decorate --all`.
