11. Протокол взаимодействия № 1
Резервирование места на мероприятии

11.1. Инициатор и получатель
Инициатор: RegistrationModule
Получатель: EventModule

11.2. Назначение
Протокол используется при создании регистрации.
Перед сохранением регистрации необходимо убедиться, что на мероприятии есть свободные места, и зарезервировать одно из них.

11.3. Механизм вызова
Асинхронный вызов через интерфейс C#:
IEventCapacityService
Зависимость передается через механизм Dependency Injection.

11.4. Точка входа
Task<ReserveSpotResult> ReserveAsync(
    ReserveSpotRequest request,
    CancellationToken cancellationToken);

11.5. Формат запроса
{
  "eventId": "8939af05-2a59-4758-a263-75df01c6d3f0",
  "registrationId": "4f7fb20d-b92c-4082-a031-7eb643216a18"
}

11.6. Успешный ответ
{
  "success": true,
  "errorCode": null
}

11.7. Ошибки
Возможные ошибки:
| Код | Описание |
|---|---|
| EVENT_NOT_FOUND | Мероприятие не существует |
| EVENT_FULL | Свободных мест нет |
| EVENT_CANCELLED | Мероприятие отменено |

Пример:
{
  "success": false,
  "errorCode": "EVENT_FULL"
}

11.8. Таймаут
Операция должна завершиться не более чем за:
3 секунды
При отмене запроса используется `CancellationToken`.

11.9. Повторная отправка
Автоматический повтор операции не выполняется.
Причина: повторный вызов без проверки может привести к двойному списанию мест (ошибке лимита).

11.10. Аутентификация
Дополнительная аутентификация между модулями не выполняется, поскольку они работают внутри одного серверного приложения.
Проверка прав пользователя выполняется на уровне API.

11.11. Версия контракта
EventCapacityContract v1

11.12. Пример обмена
RegistrationModule
       │
       │ ReserveAsync(...)
       ▼
 EventModule
       │
       │ Проверка статуса
       │
       │ Проверка лимита мест
       │
       │ Уменьшение счетчика мест
       ▼
 ReserveSpotResult
       │
       ▼
 RegistrationModule
