2. Назначение и границы проекта

2.1. Назначение системы

Разрабатываемая программная система предназначена для автоматизации создания мероприятий, управления расписанием и регистрации участников.

Пользователь системы должен иметь возможность:
- просматривать каталог предстоящих мероприятий;
- получать подробную информацию о мероприятии (дата, место, спикеры);
- регистрироваться на мероприятие;
- отменять свою регистрацию;
- просматривать историю своих регистраций и полученные билеты.

Организатор (администратор) должен иметь возможность:
- создавать и редактировать мероприятия;
- устанавливать лимиты на количество участников;
- просматривать списки зарегистрированных участников;
- отмечать факт посещения (check-in) по билету;
- отменять мероприятия.

2.2. Основные объекты предметной области
В системе выделены следующие основные сущности:
- мероприятие (Event);
- участник (User/Participant);
- регистрация (Registration);
- билет (Ticket);
- категория мероприятия.

Примеры мероприятий:
- IT-конференция;
- Бизнес-форум;
- Мастер-класс по программированию.

2.3. Границы проекта
В систему входит:
- Ведение каталога мероприятий.
- Проверка доступности мест.
- Создание и отмена регистрации.
- Генерация уникального билета (QR-код).
- Валидация билета при входе (check-in).
- Хранение информации о пользователях и их ролях.
- Просмотр истории посещений.

В систему не входит:
В рамках курсового проекта не реализуются:
- реальные банковские платежи (продажа платных билетов);
- интеграция с внешними почтовыми сервисами (отправка реальных email);
- построение интерактивных схем залов с выбором конкретных мест;
- интеграция с внешними системами аналитики;
- мобильное приложение для сканирования QR-кодов (используется веб-интерфейс).
Эти функции могут быть добавлены при дальнейшем развитии проекта.
