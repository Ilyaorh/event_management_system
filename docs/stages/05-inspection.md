# Этап 5. Инспекция кода

## Исходное состояние и область

Инспекция начата на чистой ветке `main`, коммит `55ac54e`, затем создана `stage/05-inspection`. Проверены API, контракты, сервисы мероприятий, участников, регистрации и билетов, контекст SQLite, тесты и настройки репозитория. Инспекция - ручная проверка с инструментальными командами, а не сертификация безопасности или доказательство отсутствия всех дефектов.

## Ход и результаты проверок

Тесты добавлены коммитом `647cd47`. Первый запуск 13 тестов: 12 успешно, 1 ошибка - `Reserve_RejectsNullRequestExplicitly` получил `InvalidOperationException` от EF Core вместо ожидаемого `ArgumentNullException`. Проверка `ThrowIfNull` в `a4b8878` устранила причину. Форматирование выполнено отдельно в `84be0a3`.

Финальные команды из корня репозитория:

```bash
dotnet format EventManagement.sln --verify-no-changes
dotnet build EventManagement.sln
dotnet test EventManagement.sln
```

В выполненной проверке использовались `--no-restore` для сборки и `--no-build --no-restore` для тестов после сборки: форматирование завершилось успешно, сборка - 0 предупреждений и 0 ошибок, тесты - 13 успешно, 0 ошибок, 0 пропущено. Для воспроизведения на новой машине сначала выполнить `dotnet restore` или использовать команды выше без этих флагов.

Тест `ConcurrentRequests_OnlyOneTakesLastSeat` запускает два запроса в отдельных контекстах SQLite на одно свободное место; в выполненном прогоне один успешен, второй получает `EVENT_FULL`, сохранены одна регистрация и один билет. Дополнительно тест отдельно прошёл пять запусков. Это проверка конкретного сценария, не полноценное нагрузочное тестирование и не гарантия для другой СУБД.

## Вывод и оставшиеся риски

Инспекция выявила и исправила отсутствие проверки `null` и нарушения форматирования. Подтверждены сборка, регрессия и конкретный конкурентный сценарий. Остаются ограничения учебной версии: нет входа и авторизации, миграций, автоматических HTTP- и нагрузочных тестов; используйте локально и только с учебными данными. При изменении интерфейсов, правил мест, модели БД или безопасности необходимо повторить тесты и обновить контракты и этот отчёт. Проследить изменения можно командами `git log --graph --oneline --all` и `git show <коммит>`.
