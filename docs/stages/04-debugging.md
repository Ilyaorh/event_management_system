# Этап 4. Отладка модулей

## Исходные условия

Отладка проведена в `stage/04-debugging` на интегрированной версии `33ce1d8`. Для воспроизведения подготовлены два автоматических теста в коммите `b0bee17`. Это реальные ошибки исходного кода, а не специально внесённые неисправности. Команды запускались из корня проекта с .NET SDK 9:

```bash
dotnet build EventManagement.sln
dotnet test EventManagement.sln
```

До исправлений из 9 тестов прошли 7, два воспроизводящих теста не прошли. Тесты используют временную SQLite-базу и не меняют пользовательскую базу.

## Ошибка 1. Неявная ошибка при пустом запросе билета

1. **Модуль и состояние:** `TicketService.GenerateAsync`, исходный коммит `33ce1d8`.
2. **Симптом:** вызов с `null` приводил к `InvalidOperationException` от EF Core с вложенным `NullReferenceException` при вычислении параметра LINQ. Ошибка контракта входных данных маскировалась ошибкой запроса.
3. **Воспроизведение:** тест `TicketGeneration_RejectsNullRequestExplicitly` в `b0bee17` передаёт `null` и ожидает `ArgumentNullException`. До исправления xUnit показал несовпадение типов исключения.
4. **Гипотеза 1:** метод не проверяет запрос до обращения к `request.RegistrationId`.
5. **Гипотеза 2:** регистрация отсутствует в SQLite или неправильно подготовлен контекст.
6. **Диагностика:** стек указывал на вычисление параметра LINQ и вложенное разыменование `null`, а просмотр метода показал отсутствие входной проверки. По этим данным причина - гипотеза 1; отсутствие записи не объясняет `NullReferenceException`.
7. **Исправление:** в `84f6a6d` добавлена `ArgumentNullException.ThrowIfNull(request)` до запроса к базе.
8. **Проверка:** воспроизводящий тест стал проходить; после первого исправления результат набора - 8 успешных и 1 неуспешный тест.
9. **Регрессия:** тот же тест остаётся в общем наборе и проверяет точный тип исключения. Нормальная выдача билета проверяется интеграционными тестами.

## Ошибка 2. Регистрация на уже начавшееся мероприятие

1. **Модуль и состояние:** `EventService.ReserveAsync`, исходный коммит `33ce1d8`.
2. **Симптом:** сервис выдавал билет и резервировал место для мероприятия с прошедшей датой начала.
3. **Воспроизведение:** тест `StartedEvent_CannotAcceptNewRegistration` в `b0bee17` создаёт запись с датой в прошлом и пытается зарегистрировать участника. До исправления xUnit сообщил `No exception was thrown` вместо ожидаемого `DomainException`.
4. **Гипотеза 1:** при резервировании не сравнивается дата начала с текущим временем.
5. **Гипотеза 2:** условное уменьшение числа мест неверно трактует нулевую вместимость.
6. **Диагностика:** тест задаёт свободное место, поэтому нехватка мест не является причиной. Просмотр `ReserveAsync` показал проверки состояния и остатка, но не даты - подтверждена гипотеза 1.
7. **Исправление:** в `6d40971` добавлена проверка начала перед резервированием и код `EVENT_STARTED`. HTTP-слой отображает конфликт в 409. Проверка выполняется внутри транзакции регистрации, но не заявляет отдельной гарантии для границы времени между чтением и обновлением.
8. **Проверка:** после обоих исправлений сборка прошла без предупреждений и ошибок; все 9 тестов прошли.
9. **Регрессия:** тест оставлен в общем наборе; положительные регистрации будущих мероприятий и ошибки заполненности также покрыты тестами.

## Итог

Обе причины установлены по воспроизведению и состоянию кода. Исправления выполнены отдельными коммитами, контракты и документация приведены в соответствие. Журнал выше описывает фактически выполненные проверки, а не предполагаемые результаты.
