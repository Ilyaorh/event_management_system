# HTTP API учебной версии

API не содержит аутентификации и авторизации; запускайте только локально, не используйте настоящие персональные данные. Путь базы SQLite настраивается через `ConnectionStrings__Events`. Все примеры используют `http://127.0.0.1:5090`.

## Маршруты

| Метод | Путь | Назначение / успех |
|---|---|---|
| GET | `/health` | Состояние приложения, 200 |
| POST | `/api/events` | Создать мероприятие, 201 |
| GET | `/api/events` | Список мероприятий, 200 |
| GET | `/api/events/{id}` | Получить мероприятие, 200 |
| POST | `/api/users` | Добавить участника без учётной записи, 201 |
| GET | `/api/users/{id}` | Получить участника, 200 |
| POST | `/api/registrations` | Зарегистрировать участника, вернуть регистрацию и билет, 200 |
| DELETE | `/api/registrations/{id}` | Отменить регистрацию и вернуть место, 204 |
| GET | `/api/tickets/{id}` | Получить билет, код и PNG в base64, 200 |
| GET | `/api/tickets/{id}/qr` | Получить PNG QR-кода, 200 |
| POST | `/api/tickets/check-in` | Отметить вход по коду, 204 |

Ошибки предметной области имеют форму `{"code":"EVENT_FULL","message":"..."}`. Неизвестная сущность - 404; конфликт (нет мест, мероприятие уже началось, дубликат, использованный билет) - 409; неверный ввод - 400. Некорректный JSON обрабатывается ASP.NET Core отдельно.

## Пример в Git Bash

Дата ниже примерная: замените её на будущую.

```bash
curl -sS -X POST http://127.0.0.1:5090/api/events \
  -H 'Content-Type: application/json' \
  -d '{"title":"Встреча разработчиков","description":"Учебный пример","startDate":"2035-06-15T10:00:00Z","location":"Аудитория 1","totalCapacity":20}'

curl -sS -X POST http://127.0.0.1:5090/api/users \
  -H 'Content-Type: application/json' -d '{"name":"Тестовый участник"}'
```

Скопируйте `id` из обоих ответов и подставьте в запрос регистрации:

```bash
curl -sS -X POST http://127.0.0.1:5090/api/registrations \
  -H 'Content-Type: application/json' \
  -d '{"userId":"ID-УЧАСТНИКА","eventId":"ID-МЕРОПРИЯТИЯ"}'
```

Ответ содержит `registration.id`, `ticket.id`, `ticket.uniqueCode` и `ticket.qrCodeImage`. Получить изображение: `curl -o ticket.png http://127.0.0.1:5090/api/tickets/ID-БИЛЕТА/qr`. Для отметки входа: `POST /api/tickets/check-in` с телом `{"uniqueCode":"КОД-БИЛЕТА"}`. После успешного check-in повторный вход и отмена регистрации отклоняются. Отмена до входа выполняется через `DELETE /api/registrations/ID-РЕГИСТРАЦИИ`; повторная отмена не возвращает место второй раз.

## Согласованность и ограничения

Регистрация, изменение количества мест и добавление билета выполняются в одной транзакции SQLite; при сбое выпуска билет и регистрация откатываются вместе с резервом. Обновление свободных мест выполняется условным запросом, а активная пара мероприятия и участника имеет уникальный индекс. `GenerateAsync` добавляет билет в общий контекст; вызывающий сервис сохраняет его внутри той же транзакции. Нет автоматических повторов вызовов и фиксированных 3/5-секундных таймаутов; отмена передаётся через `CancellationToken`.

QR содержит случайный код, который проверяется по базе, но подписи, входа и контроля доступа нет. Создание, редактирование и отмена мероприятий и управление правами должны быть защищены перед любым развёртыванием; редактирование/отмена мероприятий в данной версии ещё не реализованы.
