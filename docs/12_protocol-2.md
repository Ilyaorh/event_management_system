12. Протокол взаимодействия № 2
Генерация билета для регистрации

12.1. Инициатор и получатель
Инициатор: RegistrationModule
Получатель: TicketModule

12.2. Назначение
После успешного резервирования места необходимо сгенерировать уникальный билет с QR-кодом для прохода на мероприятие.

12.3. Механизм вызова
Асинхронный вызов через интерфейс:
ITicketService

12.4. Точка входа
Task<TicketDto> GenerateAsync(
    GenerateTicketRequest request,
    CancellationToken cancellationToken);

12.5. Формат запроса
{
  "registrationId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "userId": "758d711c-292a-4bcc-b2fe-77425cfe0486",
  "eventId": "8939af05-2a59-4758-a263-75df01c6d3f0"
}

12.6. Успешный ответ
{
  "id": "0597961c-c511-45db-a2cb-f197460dd21d",
  "registrationId": "4f7fb20d-b92c-4082-a031-7eb643216a18",
  "uniqueCode": "EVT-2026-A8F9-2B1C",
  "qrCodeImage": [ ... base64 bytes ... ],
  "status": "Active"
}

12.7. Ошибки
| Код | Описание |
|---|---|
| REGISTRATION_NOT_FOUND | Регистрация отсутствует |
| TICKET_ALREADY_GENERATED | Билет уже выпущен |

12.8. Таймаут
Максимальное ожидаемое время выполнения (с учетом генерации изображения):
5 секунд

12.9. Повторная отправка
Повторный запрос допускается только после проверки того, что билет для данной регистрации еще не существует.
`RegistrationId` используется как уникальный ключ для предотвращения дубликатов.

12.10. Аутентификация
Внутренняя аутентификация между модулями не требуется.

12.11. Версия контракта
TicketingContract v1

12.12. Пример обмена
RegistrationModule
      │
      │ GenerateAsync(...)
      ▼
TicketModule
      │
      │ Генерация уникального кода
      │
      │ Создание QR-изображения
      ▼
TicketDto
      │
      ▼
RegistrationModule
